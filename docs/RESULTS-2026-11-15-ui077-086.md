## Architecture change (per Duy's direction)

The suite was restructured for speed and state reuse:

- `00-fast.spec.ts` — the instant checks (map, cards, a11y, reduced motion)
  that never load data. They run first, fully parallel.
- `journey.spec.ts` — one continuous serial flow through every feature that
  loads data, sharing one browser state per project: home → search → modes →
  playback → bands/grouping → overlays → analysis → navigation → share →
  source files → compare → over time → tracks → responsive → API list →
  movers. A failing case stops the flow (later cases depend on its state).
- Worker-scoped `sharedPage` fixture: all tests on one worker share the same
  browser context; route mocks are cleaned after every case.
- `workers: 4`; at most two view loads touch the shared service at once.
- Result: full suite wall time **3–4 minutes** (was 13–30 minutes).

## Build drift handled

The production build moved twice during this work (v62, then v67). Handled
oracles: the API list gained a 22nd type (`/api/settings`, "Limits") and the
count now reflects visible rows; the map-card fade trigger moved from
`.zoomed` to `.moving`; touch height became pointer:coarse-driven. Probe
evidence for each re-grounding is in the repo history of these specs.

## Honest limits

- The mock mover/fixture cases prove the UI contract, not the server
  algorithm (no vote, measurement, or blind search ever touched prod/dev).
- Popup contract bodies are the mocks' own payloads for mocked endpoints.
- Screen reader / real device / [C] numeric oracles remain uncovered.
